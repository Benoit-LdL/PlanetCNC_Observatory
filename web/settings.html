Machine

The name is shown in the top bar and the browser tab, for everyone who opens the dashboard.

Camera

The camera panel at the top left, shown or hidden for everyone who opens the dashboard. When it is shown but no picture comes, it says why. Hiding it doesn't turn the camera off: Telegram photos, the timelapse and the camera page still use it. To turn the camera off, choose Off as the device.

Files

The folder shown in the Files tab; the Surfacing page saves its programs there. Browse… picks a folder on the Pi (a USB stick too) and saves it; Default goes back to the folder given when the server starts (--files-dir).

Tool in the 3D view

The tool size and shape are read from the tool comments this CAM program writes at the top of the G-code file. When a file has no tool comments, the diameter TNG reports for the loaded tool is used if it has one. Turned off, the standard tool marker is shown.

Telegram

Messages about jobs on your phone, with camera photos and the timelapse, from your own Telegram bot. It only reports: it can't control the machine.

Set up: in Telegram, talk to @BotFather, send /newbot and paste the token it gives here. Then send /start to your new bot, press Refresh and choose your chat.

    Messages

    Which messages the bot sends, how often it reports progress, and which arrive without sound. A silent message arrives without sound or vibration; Telegram still shows it as unread.

    A progress message goes out at whichever comes first (by percentage or by time); each message restarts the clock. Both off: no progress messages.

    Timelapse

    The camera keeps running during the job. At the end the photos become a short video (about 20 s), sent with the "Job finished" message. Long jobs take photos less often as they go. Only made when the bot and the chat are set up.

    MQTT

    Sends the machine and the Raspberry Pi to Home Assistant through an MQTT broker (the Mosquitto add-on, for example). The machine appears in Home Assistant by itself, as a device under Settings → Devices & services → MQTT: status, program, current operation, progress, time left, tool, spindle and feed, and the Pi's CPU, memory, temperature, disk, power, IP and MAC address and WiFi. It only reports: Home Assistant can't control the machine.

    With the Mosquitto add-on: the broker is Home Assistant's address, and the user name and password those of a Home Assistant user (or one set in the add-on).

    Where Home Assistant looks for new devices: homeassistant unless you changed it in Home Assistant's MQTT settings.

    The topics the values are sent on: <base topic>/progress, <base topic>/status… Leave it empty for the default.

    How often

    How often values that change all the time are sent: progress, time left, spindle and feed (machine values), and the Pi's health and network. Status, program, operation and tool are sent as soon as they change.

    Air quality

    Shows a SEN55 air-quality sensor that Home Assistant already knows (for example on an ESP32 with ESPHome) in the menu, above the Raspberry Pi: fine dust (PM2.5, PM10; PM1 and PM4 when you point at them), the VOC and NOx indexes, temperature and humidity. Read from Home Assistant every 10 seconds; it only reads, nothing is changed in Home Assistant.

    Set up: Address is how this Pi reaches Home Assistant, e.g. http://homeassistant.local:8123. For the token, in Home Assistant click your name (bottom left), open the Security tab and under Long-lived access tokens press Create token.

    The start of the sensors' entity ids: sensor.smart_sen55 for an ESPHome device with friendly_name: Smart SEN55 (Home Assistant shows them under Settings → Devices → the sensor). The PM, VOC, NOx, temperature and humidity sensors are found from it.
